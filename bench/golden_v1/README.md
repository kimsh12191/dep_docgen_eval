## 항목 폴더

| 파일 | 무엇 |
|---|---|
| `image.png` | 모델 입력. 값이 손글씨 글꼴로 채워진 그림 (1588×2246) |
| `ref.svg` | 정답. 인쇄 문구와 선은 원본 PDF 에서, 값 자리는 서식의 칸 정의에서 가져옴 |
| `check.png` | 사람이 확인하는 그림. 정답 값 자리를 그림 위에 겹쳐 그림 (파랑 = 값, 빨강 = 체크 묶음, 초록 = 도장·서명) |
| `meta.json` | 출처, 난이도와 까닭, 센 숫자, 사람 검수 여부 |

## 난이도 기준

셋 중 하나라도 윗단계면 윗단계입니다. 숫자는 `python -m formgen stats ref.svg` 로 셉니다. 경계 숫자는 가설입니다.

| | 하 | 중 | 상 |
|---|---|---|---|
| 값 자리 수 (체크 묶음 포함) | 10 이하 | 11~30 | 31 이상 |
| 체크 묶음 수 | 2 이하 | 3~10 | 11 이상 |
| 인쇄 문자 수 (공백 제외) | 600 미만 | 600~1,699 | 1,700 이상 |

새 이미지는 위 숫자를 어림해 세고, 표에서 가장 닮은 서식을 찾아 그 난이도의 통과율을 봅니다.
이 세트와 많이 다른 문서(사진, 기울어진 스캔, 여러 쪽)는 이 표로 판단하지 않습니다.

## 고른 방법과 한계

- document_gen 의 원본 서식 406종 중 1쪽짜리 241종을 위 기준으로 나누고(하 38 · 중 154 · 상 49), 서식 분류가 겹치지 않게 난이도마다 4종을 골랐습니다.
- 상은 값 자리 31~41 인 것만 골랐습니다. 값 자리가 100개가 넘는 서식은 모델 출력이 토큰 한도를 넘을 것이 뻔해 뺐습니다.
- 정답 svg 는 합쳐서 318KB 입니다. 모델 출력이 비슷한 크기라면 한 바퀴(12장)에 출력 토큰이 대략 10만 개쯤 듭니다 (어림값, 실제로 돌려 봐야 압니다).
- **정답의 값 자리는 자동으로 뽑은 칸 정의라 빠진 칸이 있습니다** (예: `hf138` 의 은행명·계좌번호 칸). 그래서 통과 기준은 정밀도가 아니라 재현율을 봅니다.
  `check.png` 를 보고 빠진 칸을 사람이 채우면 `meta.json` 의 `reviewed_by_human` 을 `true` 로 바꿉니다. 지금은 12종 모두 `false` 입니다.
- 값은 가짜이고 그림은 깨끗합니다. 실제 스캔·사진에서는 더 낮게 나올 수 있습니다.

## 다시 만들기 · 늘리기

```bash
python tools/build_golden.py --docgen /path/to/document_gen --out bench/golden_v1            # 같은 12종
python tools/build_golden.py --docgen /path/to/document_gen --out bench/golden_v2 --ids hf007 hf024 …
```

document_gen 실행 환경(브라우저 포함)과 `pymupdf` 가 필요합니다. 세트를 바꾸면 새 이름(`golden_v2`)으로 둡니다.
