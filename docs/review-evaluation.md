# 기준 템플릿 검수와 모델 평가

이 흐름은 **문서 이미지 → 값과 표 행을 바꿀 수 있는 HTML 템플릿**을 비교합니다. 프론티어 모델이 생성한 `reference/`는 정답 **초안**입니다. 사람이 검수 화면에서 승인하기 전에는 새 평가 명령에서 사용하지 않습니다. 기존 9개 문서는 자동 승인하지 않았습니다.

## 설치

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m playwright install chromium
```

OS에 Chromium 실행 라이브러리와 한글 폰트를 설치하세요. 이미 설치된 Chromium을 쓰려면 `TPLGEN_CHROMIUM=/usr/bin/chromium`을 지정할 수 있습니다. 모델 간 비교에는 같은 Chromium 버전·폰트·실행 환경을 사용하세요. 새 평가 결과에는 브라우저 버전·배율·viewport도 기록됩니다.

## 1. 기준 초안 준비

```text
evalset/v1/<문서 ID>/
  image.png                   원본 이미지 (jpg/jpeg/webp도 가능)
  meta.json                   기존 난이도 정보
  reference/
    template.html
    schema.json
    sample.json
  contract.json               공통 시험 계약 — 뷰어에서 생성·수정
  review.json                 사람 승인/반려 기록 — 뷰어에서 생성
```

프론티어 모델로 `make`를 실행한 뒤 결과 꾸러미의 세 파일을 `reference/`에 복사합니다. 기존 생성 규격은 그대로입니다. 원본 값이 틀렸으면 `sample.json`, 필드가 빠졌으면 `schema.json`과 `template.html`을 함께 수정하세요. 실서류 이미지는 기존 정책대로 사내 모델 주소에서만 처리합니다. 뷰어와 평가는 외부 모델을 호출하지 않습니다.

## 2. 뷰어에서 검수

```bash
python -m tplgen review evalset/v1
# 이미 생성한 모델 결과도 함께 보기
python -m tplgen review evalset/v1 --runs runs/exp1
```

`http://127.0.0.1:8765`를 엽니다. 다른 포트는 `--port 8766`으로 지정합니다. 로컬 전용 서버입니다. 원격 서버에서 실행하는 경우 SSH 포트 포워딩을 사용하세요.

1. 문서를 선택하고 필수 필드·표 목록을 읽습니다.
2. **시험값 저장 · 미리보기 생성**을 누릅니다.
3. 원본 이미지와 기준 렌더링을 나란히 봅니다. 확대와 스크롤 동기화를 사용할 수 있습니다.
4. 시험 선택 메뉴에서 원본 값, 새 값, 긴 값, 표의 최소·1·최대 행, bool/choice 변경을 차례로 확인합니다. 최소 행 수가 0인 표에는 0행 시험이 포함됩니다. 표별 행 수를 독립적으로 바꿉니다.
5. 시험값이 업무 범위를 벗어나면 계약 JSON의 `cases`를 수정하고 미리보기를 다시 생성합니다. 너무 긴 값이나 불가능한 행 수로 모델을 탈락시키지 마세요. 표 내부 선택형 필드는 필요하면 사례를 추가하세요.
6. 배치·내용·필드·변경 동작 확인란을 체크하고 검수자와 메모를 입력합니다. **평가 기준으로 승인** 또는 **반려**를 누릅니다.

필드 자체를 수정할 때는 `reference/` 파일도 수정해야 합니다. 초안을 처음부터 다시 만들려면 `contract.json`을 백업한 뒤 제거하고 뷰어를 다시 여세요. 기준 변경 시 기존 시험값을 무심코 유지하지 않도록 계약을 자동 덮어쓰지 않습니다.

원본 이미지, 기준 세 파일, 계약 파일의 SHA-256을 승인 기록에 묶습니다. 어느 파일이든 바뀌면 `변경됨 · 재검수`가 되고 평가가 차단됩니다. **검수 기록은 사람의 판단 기록이며 암호학적 서명이나 다중 사용자 권한 시스템은 아닙니다.** 승인되지 않은 기존 문서는 그대로 미검수 상태입니다.

뷰어는 생성 HTML을 브라우저 페이지에 직접 삽입하지 않습니다. 기존 sandbox Jinja2 및 네트워크·스크립트가 차단된 Chromium으로 렌더링한 PNG만 보여줍니다. 로컬 쓰기 요청에는 세션 토큰이 필요합니다. PNG 캐시는 `.review-cache/`에 저장되며 Git에서 제외됩니다. `contract.json`과 `review.json`은 재현성을 위해 커밋할 수 있습니다.

## 3. 모델 생성과 채점을 분리

```bash
# 기존 명령으로 모델 결과 생성 — 정답 계약은 모델이나 수정 루프에 전달하지 않습니다.
python -m tplgen bench configs/local.json

# 사람이 승인한 기준으로 최초 결과와 최종 선택 결과를 채점합니다.
python -m tplgen evaluate --dataset evalset/v1 --runs runs/exp1 --out out/exp1-reviewed
```

모든 평가 문서가 승인되어 있어야 합니다. 일부만 평가하려면 승인된 문서 폴더만 포함하는 별도 데이터셋을 지정하세요. 미검수 문서를 조용히 제외하면 모델 순위가 달라지므로 자동 제외하지 않습니다.

출력:

- `compare.md`: 모델별 최초 생성(`first`) / 수정 후 선택 결과(`final`) 비교
- `results.jsonl`: 문서별 상세 점수, 실패 이유, 매핑, 기준/후보 해시, 호출 비용과 렌더러 정보
- `<모델>/<문서>/<단계>/<시험>.png`: 실제 채점한 출력 이미지

파일이 없거나 규격이 깨진 모델 결과도 분모에 포함하며 실패로 채점합니다. 평가를 다시 실행하면 최신 승인 기준으로 재채점합니다. 최초 생성은 첫 호출만, 최종 결과 비용은 **최종 선택 회차 이후 실행분까지 모든 호출**을 합산합니다. 초는 모델 호출 시간이며 렌더링·검사 시간은 포함하지 않습니다. `total_tokens`가 모든 호출에서 제공될 때만 합산하고, 없으면 null입니다. 가격이 제공되지 않으므로 금액 비용은 추정하지 않습니다.

## 지표와 의미

| 지표 | 계산 |
|---|---|
| `valid` | 규격을 만족하고 원본 값 렌더링이 성공했는가 |
| `field_precision/recall/f1` | 필수 단일 필드·표 열과 후보의 일대일 대응률. 누락과 추가 필드를 함께 측정 |
| `sample_accuracy` | 후보가 추출한 sample로 렌더링한 필드 텍스트가 검수 기준과 일치하는 비율. 표 셀도 포함 |
| `fixed_text` | data-field/data-asset 밖의 보이는 고정 문구를 공백 정규화하고 SequenceMatcher로 비교한 유사도 |
| `change_pass_rate` | 계약에 고정된 새 값을 주입했을 때 값·행 수·고정 문구·기존 overflow/clip/overlap 검사가 모두 통과한 시험 비율 |
| `layout`, `missing` | 원본 이미지와 후보 sample 이미지의 기존 배치 유사도·최대 연속 누락 지표 |
| `pass` | 렌더링 성공, sample 시험 통과, `check.py`의 `REVIEW_RULE` 및 `MAX_MISSING` 충족 |

새 값 시험은 **후보가 만든 schema가 아니라 사람이 승인한 계약에서 생성**됩니다. 원본 재현 시험에는 후보 자신의 `sample.json`을 사용하여 잘못 읽은 값을 정답으로 덮어쓰지 않습니다. 변경 시험은 계약의 동일한 값을 각 후보 변수명으로 변환합니다. 기준 HTML의 DOM 구조나 코드 문자열 일치는 요구하지 않습니다.

변경 후 출력은 기준 템플릿이 같은 입력을 렌더링한 필드 텍스트와 비교합니다. 이 방식은 분할된 숫자나 체크박스 출력도 처리하지만, 시각적으로 동등한 다른 기호/문구 표현은 불일치할 수 있습니다. bool/choice 결과가 다른 정당한 표현이면 검수와 실패 상세를 확인하세요. 현재 버전은 의미론적 OCR 채점, 완전한 가림/가독성 판정, 픽셀 단위 라벨 정확도, 표 병합 구조 전용 지표를 제공하지 않습니다.

현재 `layout`은 빈 세로 간격을 제거하고 글꼴 차이를 허용하는 **대략적인 배치 지표**입니다. 미세한 시각 품질 순위로 해석하지 마세요. 자동 통과 기준도 임시입니다. 사람의 사용 가능 판정과 비교해 개발 세트에서 기준을 조정하고, 테스트 평가 전에 고정하세요. 기준 HTML 자체의 오류는 자동 채점으로 해결되지 않으므로 검수가 필요합니다.

## 필드 이름이 다른 경우

자동 매핑은 항목명(label)과 type을 우선 사용하고, 같은 이름으로 중복 label을 구분합니다. 표를 먼저 일대일 대응한 뒤 그 표의 열을 대응합니다. 후보의 큰 영역 하나가 여러 정답 필드를 충족할 수 없습니다. 애매하거나 의미가 다른 이름은 임의 추정하지 않고 미대응으로 남깁니다.

`runs/exp1/<모델>/<문서>/field_map.json`에 수동 대응을 지정할 수 있습니다. 이 파일은 최초·최종 결과에 공통으로 적용되므로 두 단계에서 schema가 바뀌었다면 실행을 분리하거나 이름을 정규화하세요.

```json
{
  "customer_name": "client_name",
  "transactions.amount": "rows.total",
  "optional_field": null
}
```

키는 기준 필드(표는 `표이름.열이름`), 값은 후보 필드입니다. 중복 대응·없는 경로는 오류입니다. null은 명시적 미대응입니다. 수동 매핑은 출력값을 고치지 않으며 정답을 생성 루프에 전달하지 않습니다. 의미가 맞는지 사람이 확인하고 결과와 함께 보관하세요.

## 검증

```bash
python -m unittest discover -s tests
```

새 회귀 테스트는 승인 무효화, 이름이 다른 정상 구현, 고정값/숨긴 값/누락/잘린 행 실패, 일대일 매핑, 전체 호출 비용, 브라우저에서의 승인 흐름을 검증합니다. 테스트에서 생성한 승인은 임시 폴더에만 저장됩니다.
