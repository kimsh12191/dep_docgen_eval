# docgen_eval (template-html) — 문서 이미지 → 수정 가능한 HTML 템플릿

## 왜
업무 중 들어오는 문서(은행 서식, 기관·정부 문서, 스캔·사진)를 사람이 라벨링해 KIE·문서분류 모델을 만드는 수고를 줄인다.
문서 이미지 한 장을 **수정 가능한 템플릿**으로 바꿔 두면, 값과 표 행을 바꿔 가며 **라벨이 붙은 문서 이미지를 자동으로 대량 생성**할 수 있다.

## 누가 무엇을
| 누가 | 넣는 것 | 받는 것 |
|---|---|---|
| 사용자 | 문서 이미지 1장 | **템플릿 꾸러미** (아래) |
| 외주·다른 사람 | 꾸러미 + 값(json). 값은 파이썬이나 LLM 으로 만든다 | 문서 이미지 N장 + 라벨(어느 위치에 무슨 값) |

## 템플릿 꾸러미
```
<꾸러미>/
  template.html   문서의 틀 (Jinja2). 값은 {{ 이름 }}, 반복되는 표 행은 {% for %}. 값마다 data-field 로 위치를 알 수 있게 감싼다
  schema.json     들어가는 값의 목록: 항목(fields) · 반복 표(tables) · 종류
  sample.json     원본 이미지의 내용대로 채운 예시 값
```
규칙은 [`tplgen/prompts/template_v1.md`](tplgen/prompts/template_v1.md) 가 전부다 (모델에 주는 지시문이 곧 규격).
표 행은 값 목록의 길이만큼 늘고, 아래 내용은 저절로 밀린다 — 그래서 SVG 가 아니라 HTML 이다.

## 쓰는 법
```bash
# 1) 이미지 → 꾸러미 (모델 + 셀프 고치기 루프). 설정은 configs/example.json 을 복사해 고친다
python -m tplgen make --config configs/local.json --name model_a --image samples/hf153.png --out out/hf153

# 2) 꾸러미 + 값 → 이미지 + 라벨
python -m tplgen render out/hf153/final --data my.json --out gen/0001        # 0001.png, 0001.json
python -m tplgen vary   out/hf153/final --n 20 --out gen/                    # 값을 임의로 바꿔 20장

# 3) 꾸러미가 쓸 만한가 (정답 없이 잰다)
python -m tplgen check out/hf153/final --image samples/hf153.png

# 4) 여러 모델 × 여러 이미지 비교
python -m tplgen bench configs/local.json
```

## 잘 만들었는지 재는 법 (`check`)
정답 파일 없이, **꾸러미를 실제로 돌려 보고** 잰다.

| 점수 | 뜻 |
|---|---|
| 유효 `valid` | 규칙대로이고 예시 값으로 그려지는가 |
| 닮음 `layout` | 예시 값으로 그린 그림이 원본 이미지와 배치가 닮았는가 (글꼴 차이는 봐주는 거친 비교, 0~1) |
| 견딤 `robust` | 값을 바꾸고(짧게·길게) 표 행을 바꿔(0·1·많이) 그려도 깨지지 않는 비율. 깨짐 = 넘침·겹침·값 누락·행 수 불일치 |
| 샘 `leak` | 예시 값이 틀에 고정 글자로 박혀 있는 수 (0 이어야 함) |
| 자리 수 | 항목·표·표의 열 개수 (참고) |

**쓸 만함(임시 기준) = 유효 ∧ 견딤 = 1 ∧ 샘 = 0 ∧ 닮음 ≥ 0.5.** `tplgen/check.py` 의 `PASS_RULE`.

## 지금 상태
| | |
|---|---|
| 확인함 | 본보기 꾸러미 [`examples/hf153`](examples/hf153) (표가 있는 서식. 사람이 아니라 큰 모델이 이미지를 보고 쓴 것): 표 행 1·5·20·40 으로 그려도 아래 내용이 밀리며 깨지지 않음, 값마다 라벨 위치가 나옴 |
| 확인함 | 점수가 망가진 꾸러미를 잡는가 (`tests/`): 값이 틀에 박힘 → 샘, 표 폭 고정 → 넘침, 칸 높이 고정 → 잘림, 행이 안 늘어나는 표 → 값 누락, 본문 빠짐 → 닮음 하락 |
| 확인함 | 루프: 고쳐서 나아지면 뒤 회차를, 고치다 망가지면 앞 회차를 final 로 고름. hf153 에서 큰 모델이 0회차 닮음 0.63 → 2회차 0.86 (1회차는 줄바꿈 금지를 넣었다가 긴 값 시험에서 잘려 탈락) |
| **아직 안 함** | **실제 vLLM 모델로 돌리기.** 지금까지의 꾸러미는 모두 큰 모델 하나가 쓴 것이다 |
| **아직 안 함** | 스캔·사진 입력, 서식이 아닌 문서. `samples/` 는 깨끗하게 그린 은행 서식 3장뿐 |
| **아직 안 함** | 닮음 점수와 통과 기준(0.5)이 사람 눈과 맞는지. 지금은 한 문서에서 방향만 확인 |
| 모르는 것 | 사내에서 HTML 을 그릴 수 있는가 (Playwright Chromium 이 필요). 꾸러미 만들기(모델 호출)만이면 그리기 없이도 되지만 루프와 check 는 그려야 한다 |
| 재지 않는 것 | 값이 그 칸에 어울리는가(임의 값은 종류만 맞춘다) · 값이 아닌 글자끼리 겹침 · 쪽 나눔(행이 많으면 한 장이 길어진다) |

## 폴더
| | |
|---|---|
| `tplgen/` | `make` 생성·루프 · `package` 꾸러미 읽기·검사 · `render` 그리기·라벨 · `data` 값 만들기 · `check` 점수 · `bench` 모델 비교 · `llm` · `config` |
| `examples/` | 본보기 꾸러미 |
| `samples/` | 입력 예시 이미지 (하나은행 공개 서식에 가짜 값을 채워 그린 것. 스캔·사진은 아직 없음) |
| `configs/` | 실행 설정 |

`main` 브랜치는 예전 방식(SVG 값 자리 평가)이다. **실서류 이미지는 사내 모델 주소에만 보낸다.**
